Staatslenker — Software-Architektur

Regierungssimulator · client-only Web-App · deterministischer Kern · data-driven Regelsatz

Tech-Stack

  • • TypeScript strict — eine Sprache für Kern, UI, CLI
  • • Svelte 5 + Vite — Dashboard ohne UI-Framework
  • • Zod — ein Schema für Regeln UND Saves
  • • js-yaml — Packs im Konzept-Format
  • • mulberry32 — seedbarer RNG im GameState
  • • localStorage — Saves <10 KB, kein Backend
  • • Deploy: statisch → GitHub Pages / itch.io

Determinismus & Robustheit

  • • tick(state, action, rules, rng) — pure Funktion
  • • Vorhersage auf Karten = Dry-Run desselben tick
  • • Golden-Replay: Seed → 100 Jahre → State-Hash (CI)
  • • Autosave nach jedem Tick — Tab-Crash kostet kein Jahr
  • • Pack-Loading atomisch — kaputtes Pack crasht nie
  • • Invariant-Check: clamp überall, kein NaN möglich

Build-Order

  • • 1. core: state + tick + rng + Golden-Test
  • • 2. CLI (M0) + AutoSim-Balance-Harness
  • • 3. Zod-Schema + Content (M1–M3)
  • • 4. YAML-Loader + Beispiel-Pack (M4)
  • • 5. Svelte-Dashboard (M5)
  • • 6. Saves, Score, Schwierigkeit, Audio (M6)
